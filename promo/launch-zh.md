# 发布文案样稿

## 项目简介

OpenInquire：集多家开源方法之长、按近期实测整理读取路线的中文互联网深度调研 Skill。读原帖、追评论、学视频，帮你复用已有方案、寻找选题、验证想法与准备复刻、比较既有工作。

## 社区长帖

### 我把“去各个平台搜一圈”，做成了一个调研 Skill

很多有用的经验散在小红书、知乎、公众号和视频里。作者讲一半，评论补另一半。你跟着搜几个关键词，打开一批帖子，再看几段视频，最后还要自己判断：谁说的适合我，哪些已经过时，几种说法为什么对不上。

我把这段过程整理成了 OpenInquire。

它把开源社区积累的平台接入、浏览器复用、近期检索和视频笔记方法组合起来，做成一套可以带到不同项目里的调研工作流。把找工具和整理资料的功夫，沉淀成下一次能直接用的能力。

给它一个主题，Agent 会按问题选择平台、换关键词、深入原帖和评论；需要理解视频时，再处理字幕、转写和画面。遇到技术细节，就继续追到 GitHub 的代码、Issue 和维护者讨论。

我很喜欢它处理评论的方式。这次调研就碰到一个问题帖：作者先解释是自己的配置，后来又更正原因、给出上游修复。把那几条回复读完，再打开 diff，才能把事情讲清楚。[这个例子保留了原始来源](../examples/comments-change-the-answer.md)。

实现上，我把跨平台调研流程、21个只读MCP工具、日常浏览器复用和本地视频处理组合起来。近期搜索的完整材料存到本地，Agent先看候选索引，再按问题深入；做长一点的专题，也能沿着已有来源继续查。

它可以帮你做这些事：

- **开工前先找现成的轮子。** 查清成熟方案、接入条件和真实反馈，把时间花在值得自己做的部分。
- **选题时听见真正的问题。** 看人们反复抱怨什么、现有工具遗漏什么，从材料里寻找值得验证的方向。
- **让想法有落地的起点。** 找相似实现，拆出环境、数据、步骤和验证标准，整理最小实验与复刻路线。
- **把新想法放回已有工作里比较。** 跟进论文、项目和历史讨论，列清哪些已经有人做过，差异具体在哪里。
- **把收藏变成学会。** 结合视频画面、字幕和评论，留下带时间点的笔记。

我也把“什么时候跑通过、读到了哪一层”写进验收记录。平台在变，工具在变，方法需要跟着实际结果调整。最近一轮实测日期是2026-10-11，运行前还会先检查当前入口。[验收记录](../docs/verification.md)

从一个念头，到读懂别人做过什么，再到知道自己该验证什么，调研的每一步都能留下可回查、可复用的材料。

**给一个主题，带回有出处的判断。**

## 短帖

最近把自己的跨平台调研流程做成了一个 Skill：OpenInquire。

小红书和知乎上的经验、评论里的更正、视频中的操作过程，再接上开源项目和技术讨论，可以围绕同一个问题整理。给 Agent 一个主题，让它负责搜、读、比较，最后带着来源把事情讲清楚。

找现成方案、想选题、验证与复刻、查相近工作，都能从这里开始。多家方法整合成一套流程，渠道附近期实测记录，下一次调研可以接着已有材料往下走。
